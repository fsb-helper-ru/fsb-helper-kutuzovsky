# ARCHITECTURE.md — устройство модуля «Армия» внутри ФСБ-помощника (этап 1, 07.11.2026)

Опирается на: LESSONS.md (карта проекта, N-06 «фракция не параметризована»), ARMY_FACTS.md, CONFLICTS.md.

## 1. Как устроен проект сегодня (сверено по коду, не по сайту)
- **Страница приложения** — один HTML (`shell/app.html`), собирается `tools/build.py` из 37 файлов `src/` в порядке `ORDER`;
  данные законов вшиваются из `out/laws.json`. Весь контент ФСБ (ситуации, уроки, вопросы, бланки, фразы) — данные в этих файлах.
- **Оболочка Electron** (`shell/main.js`, SHELL_API 6): окно входа `signin.html` → после входа грузит `app.html`
  (или обновлённую копию из `userData/updates/app-<ver>.html`); панель поверх игры = второе окно с той же страницей (`--fsb-role=overlay`);
  `hud.html` — мелкие подсказки. `preload.js` отдаёт странице `window.fsbNative.account = {id, login, legacy, guest}`.
- **Ключи** (`shell/lib/auth.js`): список `lic.json` `{p, s}` подписан Ed25519; `p = {app, kind:'lic', v:3, seq, ts, required, offline, msg, contact, users:[{u,k,s,e}], sup, rq}`;
  `u = sha256('FSB3U|login')[:32]`, `k = sha256('FSB3K|login|key')`; пропуск `kind:'tkt', v:1`. Аккаунт в `auth.json`: `{id, login, salt, hash, kh, created, keyAt, legacy}`.
- **Заявки** (`shell/lib/requests.js`): `FSBRQ1.<devpub>.<iv>.<ct>`, внутри `{v:1, id, login, at, ver}`; ответ `FSBRP1.<key|msg|no>.<iv>.<ct>` / `inbox.json`.
- **Центр управления** (`control/control.src.html`): пользователи `{login, key, note, s, exp, created, changedAt}`, `buildLic(seq)`, `signTicket(u)`, заявки `ST.reqs`, журнал публикаций `ST.ulog`, зашифрованная копия `users.enc.json`.
- **Обновления** (`shell/lib/updater.js`): `version.json` → `{app, version, minShell, html:{url,sha256,size}, installer:{…}, notes…}`; одна страница; `minShell` больше API → «нужен установщик».
- **Хранение данных игрока**: `localStorage` страницы, ключ `fsb_helper_kutuzovsky_v2@<accountId>`; настройки оболочки `settings.json`.
- **Поиск, оверлей, бланки, экзамен** — движки в `src/` с данными ФСБ внутри (см. LESSONS N-06).

## 2. Решение: «пакеты фракций» поверх общего ядра, две страницы в одной сборке

```
src/                 — ОБЩЕЕ ЯДРО (движок, интерфейс, поиск, оверлей, бланки-движок, экзамен-движок, учёба-движок)
src/pack_fsb*.js     — ПАКЕТ ФСБ: PACK (константы фракции) + данные ФСБ (ситуации, уроки, вопросы, бланки, фразы, группы законов…)
packs/army/*.js|css  — ПАКЕТ АРМИИ: PACK + данные Армии + тема (CSS-переменные, иконки)
out/laws.json        — законы для ФСБ (как сейчас)           out/laws_army.json — законы и правила для Армии (с провенансом)
tools/build.py --pack fsb  → shell/app.html        (как сегодня; поведение ФСБ не меняется)
tools/build.py --pack army → shell/app_army.html   (ядро + пакет Армии; ни одной строки данных ФСБ)
```
- Обе страницы лежат в установщике. До проверки ключа открывается только нейтральный `signin.html`.
- Оболочка после входа читает `account.faction` и грузит страницу своей фракции. Неизвестная/повреждённая фракция → экран «вход закрыт» с объяснением; никакой модуль не открывается (железное правило 9).
- Ядро обращается к фракционным данным только через объект `PACK` (имя, заголовки, разделы `SECTIONS/TOOLS`, группы законов, подследственность `jur`,
  печати, экзамен `exam`, подсказки поиска, ключ хранения `storeKey`, маршруты `routes`). Для ФСБ значения `PACK` равны сегодняшним строкам → поведение прежнее.
- **Граница импортов**: файл пакета одной фракции не попадает в сборку другой (это гарантирует `ORDER` сборки), а автоматическая проверка
  `tools/t_isolation.js` сканирует собранные страницы на маркеры чужого пакета (идентификаторы разделов, заголовки, ключи хранения, идентификаторы ситуаций/бланков/уроков).
- **Маршрутизатор**: `go()` принимает только маршруты из `PACK.routes` (статические разделы + динамические префиксы `a/`, `d/`, `s/`, `blanks/`, `learn/l/`);
  чужой маршрут → карточка «В этом модуле раздела нет» (без тихого отказа).

## 3. Лицензия v2 (формат записи пользователя) — совместимость сохраняется
Проводной формат списка остаётся `kind:'lic', v:3` (иначе все программы 3.6.1 отвергнут список и через 24 часа офлайна закроют вход — LESSONS, P1-подобный риск).
Версия **записи** растёт: `users[i] = {u, k, s, e, f, r, at, kid}`:
| Поле | Значение | Для старых клиентов |
|---|---|---|
| `f` | фракция `'fsb'` \| `'army'`; отсутствует = `'fsb'` | игнорируется |
| `k` | **домен хэша зависит от фракции**: ФСБ `sha256('FSB3K|login|key')`, Армия `sha256('ARMY4K|login|key')` | старый клиент считает `FSB3K` → армейский ключ **не активируется** («ключ не подходит») — армейский контент на 3.6.1 невозможен |
| `r` | роль, зарезервировано (`''`; в 4.0.0 не используется) | игнорируется |
| `at` | дата выдачи `YYYY-MM-DD` | игнорируется |
| `kid` | id ключа = первые 8 знаков `k` (для журнала аудита) | игнорируется |
Пропуск `kind:'tkt', v:1` получает те же `f`, `r`, `at`, `kid`.
Клиент (`auth.js`): фракция записи = `e.f || 'fsb'`; при активации сохраняет `acc.f`; `status()` → если `e.f !== acc.f` → код `faction`
(«ключ выдан для другой фракции — войдите через „Первый вход“ с новым ключом»); `who()` возвращает `faction`.
Один ключ = одна фракция: смена фракции = отвязка (`s:'u'`) старого + новая выдача (новый ключ, новый хэш) + запись в аудит.
Защита от подмены: фракция внутри подписанных данных; локальная правка `auth.json` (`acc.f`) → при следующем сравнении со списком `faction`; подмена ответа сервера → подпись не сходится; повтор старого списка → `seq` меньше → отвергается (уже есть).
«Серверная проверка» в этой архитектуре = подпись владельца на списке/пропуске (сервера нет; см. PROGRESS.md 3.6.1).

## 4. Заявка на ключ
Полезная нагрузка остаётся `v:1` + новое поле `rf: 'fsb'|'army'|''` (желаемая фракция, информация для владельца). Старый Центр поле игнорирует; новый показывает «просит: Армия». Фракцию присваивает только владелец при выдаче.

## 5. Изоляция
| Что | ФСБ | Армия |
|---|---|---|
| Страница | `app.html` | `app_army.html` |
| Данные игрока | `fsb_helper_kutuzovsky_v2@<id>` | `army_helper_kutuzovsky_v1@<id>` |
| Настройки оболочки (окна, горячие клавиши, оверлей) | `settings.json` | `settings.army.json` |
| Поиск, палитра, оверлей, уведомления, журнал | внутри своей страницы | внутри своей страницы |
| Тема | как сегодня | свои CSS-переменные и иконки (`packs/army/theme.css`) |
| Заголовки окон/трея/уведомлений оболочки | «ФСБ-помощник» | «Армия-помощник» (из `account.faction`) |
Аккаунт одного логина имеет одну фракцию; данные прежней фракции при смене ключа не стираются (лежат под своим ключом хранения) — DECISIONS (в).

## 6. Обновления 3.6.0/3.6.1 → 4.0.0
- Оболочка: SHELL_API 7 (фракция в аккаунте, две страницы, настройки по фракциям). `version.json` 4.0.0: `minShell: 7` → старые программы получают «нужен установщик» и ставят его сами (как 3.6.0 → 3.6.1).
- `version.json` дополняется `pages: {fsb:{url,sha256,size}, army:{…}}`; новый updater при HTML-обновлении скачивает обе страницы; старое поле `html` остаётся (= страница ФСБ) для разбора старыми версиями.
- Данные ФСБ: ключ хранения не меняется → после обновления всё на месте (тест: снимок localStorage до/после = равен).
- Откат: удерживаем прежний установщик и `version.json` 3.6.1; при проблеме — переподписать и опубликовать 3.6.1 как «latest»; программы 4.0.0 на 3.6.1 назад не откатываются сами (minShell), поэтому откат = только остановка раздачи 4.0.0 новым + инструкция.

## 7. Центр управления
Карточки-иконки «ФСБ / Армия» при создании пользователя и при выдаче ключа по заявке; значок фракции в таблице; фильтр по фракции; статистика по фракциям;
журнал аудита `ST.audit` (в зашифрованной копии): выдача, новый ключ, отвязка, блокировка, смена фракции (= отвязка + выдача), с датой и фракцией;
«Перевыпустить» = отвязать + выдать новый ключ (с выбором фракции). Поле `rf` заявки показывается подсказкой. Сообщение для отправки упоминает фракцию.

## 8. Контент Армии
`tools/build_data_army.py` собирает `out/laws_army.json`: документы с полями `prov = {src, url, fetched, sha256, edition, status}`, где `status` ∈ {`verbatim-unofficial-copy` (дословная копия из неофициального репозитория, структура сверена с вики), `retelling` (пересказ по пунктам с форума, помечается в интерфейсе «пересказ»)}.
Порядок подборки: ФЗ о ВС → ФКЗ о ЧП и ВП → ПГО (разд. 6–7 первыми) → правила базы/Air Drop/поставок/Форта/ВП → ФЗ об оружии → о гостайне → УК → ПК → КоАП → Конституция → смежные.
Справочник отделов: `packs/army/units.js` — записи `{id, name, status:'confirmed'|'proposal'|'unverified', src, approvedBy, approvedAt}`; включение/выключение/переименование — через Центр управления (поле `units` в подписанном списке `p.ext.army.units`, опционально) и локально.

## 9. Экзамен и учёба (ядро параметризуется `PACK.exam`)
ФСБ: 30 вопросов / 25 мин / 95 % (как есть). Армия: 50 вопросов / 40 мин / 95 % (48 из 50; 47 — нет), банк ≥150, новый набор при каждой попытке, аннулирование при уходе — общий код quiz2.js.
